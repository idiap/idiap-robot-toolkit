# Contributing

## Commit message guidelines

Following the [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/), the commits
should start with on of the following keywords:

- `build`: when related to how the env should be built
- `chore`: when doing grunt tasks
- `ci`: when related to the CI/CD pipelines
- `docs` : when related to the documentation
- `style`: when the change does not affect the meaning of the code
- `feat`: when a new features is implemented
- `refactor`: when refactoring the code
- `perf`: when improving the performance
- `test`: when adding or updating a unittest
- `fix`: when fixing a bug
